    The problem

    Your agent has a wallet. That's the attack surface.

    An AI agent with a private key can do anything the key can do. One poisoned web page, one leaked env file or one bad loop, and the money is gone. Killswitch makes the worst case small and known in advance.

    Threat 01

    Prompt injection

    A page tells your agent to "pay this invoice" to an attacker. The agent believes it and signs.

    → flagged as a drain pattern; rejected, agent paused
    Threat 02

    Leaked session key

    The key ends up in a log or a repo. The attacker skips our relay and calls the chain directly.

    → caps still bind on-chain; indexer pauses the agent
    Threat 03

    Runaway loop

    A bug makes the agent retry the same trade a hundred times, each one "valid" on its own.

    → the period cap reverts with CapExceeded
    How it works

    Five checks. Every call. On-chain.

    Each agent action runs through _run() inside your wallet contract. If any step fails, the whole transaction reverts and nothing moves.

    Allowlist CallNotAllowed

    Only approved contracts and functions. Approvals can only go to contracts the agent may already call.

    Snapshot balances

    Record every capped token before anything runs.

    Execute

    Run the agent's signed calls exactly as signed. The relayer can't change a byte.

    Measure real outflow CapExceeded

    Spend is the balance difference, not what the call claims. Over the cap means revert.

    No leftovers DanglingAllowance

    Any token approval still open after the call kills the transaction.

    Guardian

    Every operation gets a risk score.

    Before an agent's operation reaches the chain, the guardian simulates it and adds up risk signals. Tick the signals below to see how it decides. These are the real weights from the guardian.

    Emergency stop

    One button. Every agent. Gone.

    No hunting down keys, no revoking agents one by one. A single transaction from your wallet ends every grant at once. The guardian can also pause a single agent the moment something looks wrong.

    Why on-chain

    Policies on a server can be switched off. Yours can't.

    Hosted agent wallets enforce limits on the provider's servers. Killswitch enforces them in a contract you own. Even if every server we run were breached, your caps would still hold.

    Hosted agent walletKillswitch
    Where limits are enforcedProvider's serversYour wallet contract, on-chain
    If the provider is breachedLimits can be bypassedCaps still hold
    Keep your existing walletNew custodial accountYour MetaMask stays the owner
